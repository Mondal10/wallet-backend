# Wallet Backend API

A RESTful wallet system built using **Node.js, Express, MongoDB Atlas, and Mongoose**.

Hosted postman collection available [here](https://documenter.getpostman.com/view/52395210/2sBXcBo2uN).

Supports:

- Wallet setup
- Credit / Debit transactions
- Fetch wallet details
- Fetch paginated transactions

---

## Tech Stack

- Node.js
- Express.js
- MongoDB Atlas
- Mongoose

# Database Models

## Wallet Model

| Field       | Type       | Required | Default | Description                                              |
| ----------- | ---------- | -------- | ------- | -------------------------------------------------------- |
| `_id`       | ObjectId   | Yes      | Auto    | Unique wallet identifier (generated by MongoDB)          |
| `name`      | String     | Yes      | —       | Unique wallet name                                       |
| `balance`   | Decimal128 | No       | 0       | Current wallet balance (stored with 4 decimal precision) |
| `createdAt` | Date       | Auto     | Auto    | Wallet creation timestamp                                |
| `updatedAt` | Date       | Auto     | Auto    | Last updated timestamp                                   |

### Notes

- `name` is unique.
- `balance` uses MongoDB `Decimal128` for precision.
- Timestamps are automatically managed.

---

## Transaction Model

| Field         | Type                    | Required | Description                                          |
| ------------- | ----------------------- | -------- | ---------------------------------------------------- |
| `_id`         | ObjectId                | Yes      | Unique transaction ID (generated by MongoDB)         |
| `walletId`    | ObjectId (ref: Wallet)  | Yes      | Reference to associated wallet                       |
| `amount`      | Decimal128              | Yes      | Transaction amount (stored with 4 decimal precision) |
| `balance`     | Decimal128              | No       | Wallet balance after transaction                     |
| `description` | String                  | No       | Transaction description (trimmed)                    |
| `type`        | String (credit / debit) | Yes      | Transaction type                                     |
| `createdAt`   | Date                    | Auto     | Transaction creation timestamp                       |
| `updatedAt`   | Date                    | Auto     | Last updated timestamp                               |

# API Endpoints

## 1. Setup Wallet

**POST** `/wallet/setup`

### Request Body

```json
{
  "name": "Wallet A",
  "balance": 10.5
}
```

### Response

```json
{
  "id": "walletId",
  "balance": 10.5,
  "transactionId": "transactionId",
  "name": "Wallet A",
  "date": "2026-02-14T10:00:00.000Z"
}
```

---

## 2. Make Transaction

**POST** `/transaction/transact/:walletId`

### Request Body

```json
{
  "amount": 5.25,
  "description": "Recharge",
  "type": "credit"
}
```

### Response

```json
{
  "id": "transactionId",
  "balance": 15.75
}
```

---

## 3. Get Wallet Details

**GET** `/wallet/:walletId`

### Response

```json
{
  "id": "walletId",
  "balance": 15.75,
  "name": "Wallet A",
  "date": "2026-02-14T10:00:00.000Z"
}
```

---

## 4. Fetch Transactions

**GET**

```
/transaction/transactions?walletId=walletId&skip=0&limit=10
```

### Response

```json
{
  "skip": 0,
  "limit": 10,
  "total": 1405,
  "transactions": [
    {
      "id": "transactionId",
      "walletId": "walletId",
      "amount": 5.25,
      "balance": 15.75,
      "description": "Recharge",
      "date": "2026-02-14T11:00:00.000Z",
      "type": "credit"
    }
  ]
}
```

---

## 5. Export Transactions

**GET**

```
/transaction/:walletId/export
```

### Response

`csv file`

# Precision Handling

- Monetary values are stored using **MongoDB Decimal128**
- All balances and amounts are normalized to **4 decimal precision**
- Decimal values are converted to Floating point number before sending API response

---

# Pagination

- `skip` → must be non-negative integer
- `limit` → must be positive integer
- Transactions sorted by default to newest first (No API support for now)

---

# Error Handling

- Centralized error middleware
- Proper HTTP status codes:
  - 400 → Validation error
  - 404 → Resource not found
  - 500 → Server error
